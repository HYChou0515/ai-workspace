# PM 甘特圖:緊急程度、上色來源、收合、以及以週為主的時間軸

> 狀態:**grill 完成,尚未實作**。
> 來源:七項使用者需求(見 §1),經一輪問答收斂為 §2 的決定。

**一句話**:讓同一張甘特圖能回答不同問題(照什麼上色、照什麼分組)、看得懂時間(以週為主的軸)、
而且兩個既有的甘特 view 不再各自漂移。

---

## 1. 原始需求

1. issue 要有緊急程度,並且能在甘特圖上用顏色看
2. 甘特圖要能依不同欄位上色(狀態、緊急度、負責人…)
3. 甘特圖的群組要能收合
4. Workload 和 Timeline 顯示不一致
5. 第一欄的標題太長會被截斷,滑鼠移過去要能看到完整標題
6. 時間軸的表頭要 sticky,捲下去還看得到
7. view 要能設定「永遠顯示週別」;另外希望用 `1 2 3 4 5` 表示週幾(也支援英文縮寫,但偏好數字)

## 2. 查證與決定

### 2.1 第 4 點的前提不成立(已查證)

`workload.ai.yaml` 和 `gantt.ai.yaml` **都是 `view: gantt`**,用的是同一個 `GanttView.tsx`。
顯示不同是因為兩個檔案各自從零開始寫設定,而 Workload 少了四個區塊:

| | Timeline | Workload |
|---|---|---|
| `group_by` | milestone | assignee |
| `week:` | 有 | **無** → 時間軸退回日/月標籤 |
| `skip_weekends` | true | **無** → 週末照畫 |
| `schedule:` | 有 | **無** |
| `assignee:` | 有 | **無** |

**照「合併元件」修會什麼都修不到。** 真正的問題是每個 view 檔都從空白開始。

### 2.2 決定表

| # | 問題 | 決定 |
|---|---|---|
| Q1 | 上色來源誰決定? | **使用者在畫面上切,存回 view 檔**。理由:同一張圖換個問法本來就不是兩張圖;若做成「作者在每個 YAML 各寫一次」,就是第 4 點那個坑再挖一個 |
| Q2 | 緊急程度的尺度? | **`critical` / `high` / `medium` / `low`**,紅/橙/藍/灰。**不必填**(沒設 = 中性灰),**有序**(排序得起來,顏色紅→灰而不是雜湊配色) |
| Q3 | 兩張圖該差在哪? | **只差 `group_by`,其餘全部一致**。Workload 也能重排、也有頭像欄 |
| Q4 | 收合狀態存哪? | **瀏覽器,每人自己**。顏色是「這張圖在問什麼」(該共用),收合是「我現在在看哪一段」(不該替別人決定)。**兩者刻意存在不同地方,程式碼要寫明原因**,免得下一個人順手統一 |
| Q5 | 幾號要不要留? | **做成設定,不硬切**。使用者原話:「要有足夠的設定即可」 |

### 2.3 view 檔是每個 item 一份

`views/*.ai.yaml` 在 item 建立時 seed 進該專案的 workspace,所以**同一個專案的人共用一份**。
這是 Q1(顏色存 view)和 Q4(收合存瀏覽器)分道揚鑣的理由。

## 3. 以週為主的時間軸(第 7 點重新設計)

加上「週幾」之後,原本問的「要不要永遠顯示 week」被吸收掉了——軸的主角本來就該是週:

| 密度 | 粗列 | 細列 |
|---|---|---|
| 最密(日) | `W2601` | `1 2 3 4 5` |
| 中 | 月份 | `W2601` `W2605`…(跳著標) |
| 疏 | 年 | 月份 |

- 前兩個密度週別本來就一直在,所以 `always_week` 只管**最疏那一端**:打開的話縮到最小也不換月份,繼續跳著標週別。
- `skip_weekends: true` 時一週五格,`1..5` 剛好填滿;沒開就是 `1..7`。
- 週幾的表示法是設定(數字 / 英文縮寫),**預設數字**。
- 幾號同樣是設定(不顯示 / 常駐小字 / hover)。

## 4. 現況(已查證)

- `issue` schema **沒有**緊急程度欄位
- `GanttView` **完全沒有依欄位上色**的邏輯
- 取色引擎**已經存在**:`selectColor.ts`,看得懂 schema 的 `colors:` 對應,table/board 的彩色 chip 就是它
- 第一欄 `.ev-gantt__row-label` 有 `text-overflow: ellipsis`,但 `GutterRow` **沒有 `title` 屬性**——所以截斷之後真的無從得知
- 軸的細列**依密度**在日/週/月之間切換(`AXIS_MIN_LABEL_PX`),不是依 zoom 檔位

## 5. Phases

> 一個 phase 一個 commit,flat integer。每個 phase 都要有**會紅的新測試**。

### P1 · 緊急程度欄位

`issue/schema.yaml` 加 `urgency`,四級 + `colors:`。不必填。表格/看板自動拿到彩色 chip
(`selectColor` 已經支援),所以這個 phase 本身就有可見成果。

### P2 · 甘特圖依欄位上色

`GanttView` 的長條依所選欄位取色,沿用 `selectColor`——**不新增第二套配色**,否則同一個
`status` 在 chip 和長條上會是兩個顏色。未設值走中性灰。

### P3 · 上色來源的使用者控制 + 存回 view

工具列一個選單,可選的是「能上色的欄位」(status / urgency 這類 select,加上 assignee)。
選完存回 view 檔,和排序現在的做法一致。

### P4 · 群組收合

per-user,存瀏覽器。key 要含 item + view,否則兩個專案會互相干擾。

### P5 · Workload 與 Timeline 對齊 + 甘特預設收斂

先把 Workload 補成「只差 `group_by`」,再把甘特的呈現預設收到一處,view 檔只寫要覆寫的。
**測試要釘住「新增第三個甘特 view 不必重抄設定」**,否則這個 phase 等於只是複製貼上。

### P6 · 第一欄完整標題

`GutterRow` 加 `title`。群組標籤同樣處理——它也會截斷。

### P7 · sticky 表頭

表頭在捲動時固定。注意它會**永久佔用版面**,所以第 3 節那些「多一列」的設定要一起考慮
高度。

### P8 · 以週為主的軸

`ganttScale` 的細列改成週幾;`always_week`、週幾表示法、幾號顯示方式三個設定。
這個 phase 最大,而且會動到既有的軸測試(`ganttScale.test.ts` 477 行)。

## 6. 明確不做

- **不合併 GanttView 和「workload 元件」** —— 沒有第二個元件(§2.1)
- **不新增第二套配色** —— `selectColor` 已經是那套
- **收合狀態不存 view 檔** —— 那會讓一個人的閱讀狀態變成全專案的設定(Q4)
